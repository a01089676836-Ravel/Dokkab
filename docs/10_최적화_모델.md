# 최적화 모델: ONNX → TensorRT 변환

- **작성일**: 2026-10-06
- **관련 파일**: `optimization/convert_trt.sh`, `optimization/benchmark_trt.py`, `optimization/yunet_fp32.engine`, `optimization/yunet_fp16.engine`
- **성능 비교**: [벤치마크 결과](11_벤치마크_결과.md)

## 1. 목적

현재 `convey_vision.py`는 YuNet ONNX 모델을 OpenCV(`cv2.FaceDetectorYN`)로 **CPU에서** 실행한다. Jetson에 설치된 OpenCV는 CUDA를 쓰지 않도록 빌드되어 있다(`cv2.cuda.getCudaEnabledDeviceCount()` = 0). 모델을 TensorRT 엔진으로 바꿔 GPU에서 실행하면 검출 속도를 높이고 CPU 부담을 줄일 수 있는지 확인했다.

## 2. 원본 모델과 환경

| 항목 | 값 |
|---|---|
| 원본 모델 | `face_detection_yunet_2023mar.onnx` (232,589 bytes, md5 `4ae92eeb150c82ce15ac80738b3b8167`) |
| 입력 | `input` 1×3×640×640 (고정 크기, BGR, 0~255 실수, 정규화 없음) |
| 출력 | stride 8·16·32별 `cls`, `obj`, `bbox`, `kps` 12개 (예: `bbox_8` 1×6400×4) |
| 장비 | Jetson Orin Nano, JetPack 6 (L4T R36.4.7), 전원 모드 15W |
| 변환 도구 | TensorRT 10.3.0 `trtexec` (`/usr/src/tensorrt/bin/trtexec`) |

## 3. 변환 절차

```bash
cd ~/Dokkab/optimization
./convert_trt.sh
```

스크립트가 실행하는 명령은 다음 두 줄이다.

```bash
trtexec --onnx=../face_detection_yunet_2023mar.onnx --saveEngine=yunet_fp32.engine
trtexec --onnx=../face_detection_yunet_2023mar.onnx --fp16 --saveEngine=yunet_fp16.engine
```

ONNX 파서가 모델 전체를 오류 없이 읽었고(`parse True`), 두 변환 모두 `PASSED`로 끝났다. 빌드 로그는 `optimization/build_fp32.log`, `build_fp16.log`에 있다.

## 5. 엔진 실행 방법

`optimization/benchmark_trt.py`의 `TrtDetector`가 엔진을 실행한다. OpenCV `FaceDetectorYN`과 같은 결과가 나오도록 아래 순서를 그대로 따랐다.

1. **전처리**: 640×480 카메라 프레임 아래쪽을 0으로 채워 640×640으로 만들고, 채널 순서를 HWC → CHW로 바꾼다. 엔진 입력 크기가 고정이기 때문이다. 위쪽 480줄의 좌표는 바뀌지 않으므로 상자 좌표를 따로 되돌릴 필요가 없다.
2. **추론**: TensorRT 10 API(`execute_async_v3`)로 실행한다. GPU 메모리 할당·복사는 `libcudart`를 `ctypes`로 직접 호출한다. `pycuda`가 설치되어 있지 않아서 새 패키지를 깔지 않으려고 이렇게 했다.
3. **디코딩**: stride별로 점수 = √(cls × obj), 중심 = (격자 위치 + 예측값) × stride, 폭·높이 = exp(예측값) × stride로 계산한다. OpenCV `FaceDetectorYN` 내부 방식과 같다.
4. **NMS**: `cv2.dnn.NMSBoxes`로 score 0.8, NMS 0.3, top_k 5000을 적용한다. `convey_vision.py`와 같은 값이다.

TensorRT 파이썬 모듈은 시스템 `python3`에만 있어서, 엔진 측정은 `python3`으로 실행한다. 두 환경의 OpenCV 버전은 모두 4.14.0이다.

## 6. 적용 여부

**`convey_vision.py`에는 적용하지 않았다.** 이유는 세 가지다.

- 잘 동작하는 메인 프로그램을 수정하지 않기로 했다.
- 측정 결과 실제 처리 속도 향상은 FP16에서 1.23배로 크지 않았다. 지금 프로그램의 속도 한계는 카메라(22fps)이고, 검출(OpenCV 기준 71 FPS)이 아니다. 자세한 내용은 [벤치마크 결과](11_벤치마크_결과.md)에 있다.
- 가장 큰 이점은 CPU 사용 감소(558% → 65%)다. 이 이점은 CPU를 많이 쓰는 기능(사람 전체 검출 등)을 더할 때 의미가 커진다.

적용하려면 `convey_vision.py`의 `cv2.FaceDetectorYN.create(...)`를 `TrtDetector`로 바꾸고, `detector.detect(frame)`이 돌려주는 형식(상자 배열)을 맞추면 된다.
