계획서: 무엇을 만들고 무엇을 뺐나

작업자 접근을 카메라로 감지해 경고하고, 위험 거리에서 벨트를 멈추는 시제품 계획입니다. 수정본은 실제 장비에서 해 보며 바뀐 범위를 반영했습니다.

문제: 움직이는 벨트 옆의 작업자

작업자는 작업에 집중하느라 장비와의 거리를 놓치기 쉽고, 관리자는 모든 순간을 지켜볼 수 없습니다. 그래서 자동 감지, 먼저 경고, 위험하면 정지, 기록 남기기를 요구사항으로 정했습니다.

  • 같은 Wi-Fi나 인터넷 주소로 다른 기기에서 보기. 종료·DB 버튼만 비밀번호

이벤트는 Jetson의 로컬 대기함에 먼저 저장되고, 별도 스레드가 5초 간격으로 Aiven MySQL에 보냅니다. 인터넷이 끊겨도 기록이 남고, 벨트 제어 루프는 네트워크를 기다리지 않습니다.

                     conveyor_event_logs
                                ▲

설계 포인트

  • 발생 시각과 수신 시각 분리: 늦게 전송돼도 실제 발생 시각 유지

  • occurred_at_utc 인덱스: 최신순 조회

최적화: YuNet ONNX를 TensorRT FP32·FP16 엔진으로 변환

지금 프로그램은 YuNet을 OpenCV로 CPU에서 돌립니다(이 OpenCV는 CUDA 미사용). 같은 모델을 GPU에서 돌리는 TensorRT 엔진 두 개를 만들고, OpenCV와 같은 결과가 나오도록 전처리·디코딩·NMS를 맞췄습니다.

변환 절차 (optimization/convert_trt.sh)

FP32trtexec --onnx=… --saveEngine=yunet_fp32.engine
FP16trtexec --onnx=… --fp16 --saveEngine=yunet_fp16.engine

결과물

엔진크기 · 빌드 시간
원본 ONNX232,589 bytes · 입력 1×3×640×640 고정
yunet_fp32.engine743,996 bytes · 71.6초
yunet_fp16.engine564,628 bytes · 129.1초

엔진 실행 순서 (TrtDetector)

1 전처리640×480 프레임 아래쪽을 0으로 채워 640×640, HWC → CHW
2 추론execute_async_v3, GPU 메모리는 libcudart를 ctypes로 호출(새 패키지 설치 없음)
3 디코딩점수 = √(cls × obj), 중심·크기는 stride 8·16·32 격자 기준. OpenCV 내부 방식과 같음
4 NMSscore 0.8, NMS 0.3, top_k 5000 (convey_vision.py와 같은 값)

된 것

  • ONNX 전체 파싱 성공, 두 변환 모두 PASSED
  • OpenCV와 같은 디코딩으로 결과 98% 일치 (11 벤치마크)

주의할 점

  • 엔진은 만든 장비·TensorRT 버전에서만 동작. 다른 Jetson에서는 다시 변환
  • 메인 프로그램(convey_vision.py)에는 적용하지 않음. 지금 속도 한계는 카메라(22fps)
