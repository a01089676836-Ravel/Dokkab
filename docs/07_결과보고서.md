# 결과보고서

비전 AI 기반 컨베이어 작업자 접근 감지 및 안전 알림 시스템

- **과정**: 온디바이스 AI 기반 산업용 소프트웨어 개발 1기
- **팀**: 전종현(팀장), 송태원, 장호영
- **작성일**: 2026-10-01

## 1. 요약

Jetson Orin Nano에 연결한 웹캠으로 작업자의 얼굴을 검출하고 거리를 추정했다. 50~200cm에서는 노랑 LED로 경고하고, 50cm 이내에서는 컨베이어 벨트(DC 모터)를 정지했다. 모든 상태 변경과 정지 이유는 Aiven MySQL에 저장되고, HTML 대시보드에서 카메라 화면과 함께 실시간으로 볼 수 있다.

## 2. 시스템 구성

```
USB 웹캠 ─▶ YuNet 얼굴 검출 ─▶ 거리 추정 ─▶ 상태 판단 + 1초 안정화
                                                   │
                     ┌─────────────────────────────┼──────────────────────┐
                     ▼                             ▼                      ▼
             LED(15 빨강, 31 노랑)        L9110S → DC 모터(벨트)     로컬 대기함 → Aiven MySQL
                                                                          │
                                         HTML 대시보드 ◀── Flask ◀────────┘
                                         (왼쪽 카메라, 오른쪽 로그)
```

| 구분 | 내용 |
|---|---|
| 하드웨어 | Jetson Orin Nano, USB 웹캠, 브레드보드, 빨강·노랑 LED, L9110S, DC 모터 |
| AI 모델 | OpenCV YuNet (`face_detection_yunet_2023mar.onnx`, 사전학습) |
| 소프트웨어 | Python 3.10, OpenCV 4.14.0, Jetson.GPIO, Flask, PyMySQL |
| 저장 | Aiven MySQL (`conveyor_event_logs`), 로컬 SQLite 전송 대기함 |
| 실행 파일 | `convey_vision.py` 하나로 비전·제어·기록·대시보드 실행 |

## 3. 계획 대비 변경

| 항목 | 계획 | 최종 | 이유 |
|---|---|---|---|
| 입력 | 카메라 + 온도·초음파 센서 | 카메라만 | 센서-보드 통신 문제로 범위 조정 |
| 출력 | LED + 서보모터 | LED + DC 모터(L9110S) | 컨베이어 벨트 구동에 맞춤 |
| 경고 동작 | 파란 LED | 노랑 LED + **벨트 작동 유지** | 불필요한 정지 방지, 위험 때만 정지. LED는 대시보드 신호등 색과 맞춰 노랑으로 교체(2026-10-06) |
| 대시보드 접속 | (명시 없음) | 같은 Wi-Fi + 인터넷 주소 (보기는 자유, 종료·DB 버튼만 비밀번호) | 장비 밖에서도 상태 확인 |
| 기록 | SQLite/CSV | Aiven MySQL + 로컬 대기함 | 원격 조회, 네트워크 장애 대비 |
| 카메라 | 인덱스 1 | 인덱스 0 | Jetson 연결 기준 |

## 5. 문제 해결 과정

| 문제 | 원인 | 해결 |
|---|---|---|
| Windows에서 `No module named 'Jetson'` | 코드를 PC의 Windows Python으로 실행 | VS Code Remote-SSH 설정을 고쳐 Jetson에서 실행 |
| 벨트가 반대로 동작 (빨강에서 작동, 초록에서 정지) | 모터 드라이버 입력 하나(B-1B)가 미연결 상태로 HIGH | 33번 LOW=작동, HIGH=정지로 코드를 배선에 맞춤 |
| 경고 거리에서 벨트가 덜컥거림 | 얼굴 검출이 끊겨 상태가 정상↔경고 반복 | 안전 쪽 전환에 1초 유지 조건 추가 |
| 대시보드에서 모터가 전혀 동작 안 함 | 무해한 `/dev/mem` 경고를 pinmux 오류로 오인 | 실제 pinmux 경고만 오류로 처리 |
| `Device or resource busy` | 이전 실행 프로그램이 핀을 계속 잡고 있음 | 하나만 실행, 종료 절차 정리 |
| 웹캠 프레임 수신 중단 | USB 웹캠 스트림 멈춤 | USB 재연결 |
| 비밀번호 입력 뒤 프로그램이 꺼짐 | 비밀번호 첫 글자 `q`가 Jetson 카메라 창의 종료 키로 들어간 것으로 추정 (트레이스백 없는 정상 종료, PC 브라우저로는 재현 안 됨) | `q`·`s`가 없는 비밀번호로 교체 |
| DB 연동을 끈 뒤 다시 켜지지 않음 | 끄기 전에 보낸 로그 조회 응답(2~3초)이 늦게 도착해 버튼을 "꺼짐"으로 덮어씀 | 버튼을 누른 뒤 도착한 옛 응답은 버리고, 정상 응답이면 "켜짐"으로 맞춤 |
| 종료 버튼 뒤 웹에서 다시 켤 수 없음 | 종료 버튼은 프로세스 자체를 끝냄 | `launcher.py`가 프로그램을 지켜보다 꺼지면 [다시 시작] 화면 제공 (`convey_vision.py`는 수정 안 함) |

## 6. 한계

1. **얼굴이 보여야만 검출된다.** 뒤돌아선 작업자, 마스크·안전모로 가린 얼굴은 놓친다(미탐 M1).
2. **거리는 추정값이다.** 얼굴 크기 기반 근사식(13000 ÷ 상자 높이)이라 사람마다, 각도마다 오차가 있다. 운영 로그에는 정답 거리가 없어, 현장 정확도·F1·거리 오차는 `evaluate_model.py`로 따로 측정해야 한다.
3. **추정거리가 흔들린다.** 같은 위치에서 139.8cm ↔ 342.1cm로 급변한 사례가 있다.
4. **TensorRT 엔진은 만들었지만 메인 프로그램에는 적용하지 않았다.** 속도 향상은 FP16에서 1.23배로 작았다. 원래 모델도 카메라(22fps)보다 빨라, 현재 속도의 한계는 카메라와 화면 표시다. 큰 이점은 CPU 사용 감소(558% → 65%)다. 반면 메모리는 늘었다(프로세스 최대 RSS 357MB → 560MB).
8. **인터넷 주소가 켤 때마다 바뀐다.** 계정 없는 Cloudflare 임시 터널이기 때문이다. 고정 주소는 Cloudflare 계정과 도메인이 필요하다. 또 영상·로그는 비밀번호 없이 공개되어 화면에 찍힌 얼굴이 주소를 아는 사람에게 보인다. 같은 Wi-Fi의 `http` 접속에서는 버튼 비밀번호가 암호화되지 않고 오간다(인터넷 주소는 `https`).
5. **USB 웹캠이 가끔 멈춘다.** 재연결이 필요하다.
6. **모터 드라이버 입력 하나가 미연결**이라 모듈 기본값(HIGH)에 의존한다.
7. **Jetson 모니터에 로그인된 상태에서만 정상 실행된다.** 모니터 창을 열 수 없으면 프로그램이 Qt 오류로 비정상 종료(종료 코드 134)하고, 이때는 벨트 정지 코드가 실행되지 않는다. 종료 후 핀이 해제될 때 벨트가 멈춘 상태로 유지되는지도 하드웨어로 확인해야 한다.

## 7. 개선 방향

1. 사람 전체 검출 모델(YOLO person 등)을 함께 써서 얼굴이 안 보이는 경우를 보완한다.
2. `evaluate_model.py`로 정답 거리가 붙은 평가 데이터를 모아 Accuracy·F1을 측정하고, `yunet_distance_calibration.py`로 거리식을 다시 맞춘다.
3. 거리값에 이동평균을 적용해 흔들림을 줄인다.
4. 만들어 둔 TensorRT FP16 엔진을 메인 프로그램에 적용하고, 전처리·후처리를 최적화해 CPU 여유를 확보한다. 이 여유를 사람 전체 검출 같은 추가 모델에 쓴다.
5. 모터 드라이버 B-1B를 GPIO 핀이나 GND에 연결해 배선을 확정한다.
6. 웹캠 프레임이 끊기면 자동으로 다시 여는 기능을 넣는다.
