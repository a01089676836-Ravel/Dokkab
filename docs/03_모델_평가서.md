## 3. 현장 지표 (운영 로그 기반)

### 3.1 측정할 수 없었던 지표

정확도·F1·거리 오차는 **정답(실제 거리)이 필요**하다. 운영 로그에는 시스템이 추정한 값만 있어서 로그로는 계산하지 않았다. 정답을 붙인 평가 데이터를 따로 모아 5장의 방법으로 계산한다.

### 3.2 상태 안정성 (깜빡임)

얼굴 검출이 프레임마다 끊겼다 이어지면 상태가 정상↔경고로 계속 바뀐다. 벨트 제어가 흔들리는 원인이 되므로 이를 핵심 지표로 측정했다.

**지표 정의**: 상태가 바뀐 뒤 1초 안에 다시 바뀐 횟수의 비율(1초 미만 반전 비율)

| 구간 | 기록 | 상태 전환 | 1초 미만 전환 | 비율 |
|---|---|---|---|---|
| 필터 적용 전 | 1,677건 | 1,661회 | 1,353회 | **81.5%** |
| 필터 적용 후 (10-01) | 39건 | 30회 | 5회 | **16.7%** |
| 필터 적용 후 (10-01 ~ 10-06 전체) | 507건 | 483회 | 65회 | **13.5%** |

- **필터**: 더 위험한 쪽(정상→경고→위험)은 즉시 바꾸고, 안전한 쪽은 1초 동안 계속 유지될 때만 바꾼다.
- 필터 적용 후 남은 1초 미만 전환은 모두 **더 위험해지는 전환**이다. 10-06 재계산의 65회는 정상→경고 51회, 경고→위험 9회, 정상→위험 5회였다. 안전을 위해 즉시 적용하도록 설계한 동작이다. 안전 쪽(경고→정상, 위험→경고)으로 1초 안에 되돌아간 전환은 0회다.
- **재계산 (2026-10-06)**: 10-01 기록만으로는 표본이 39건뿐이라 예비 결과였다. 10-06까지 쌓인 필터 적용 후 로그 507건(전환 483회)으로 같은 방법을 다시 적용해 **13.5%**를 얻었다. 계산 방법은 같은 코드로 기존 값(81.5%, 16.7%)을 그대로 재현해 확인했다.
- **남은 한계**: 필터 후 로그는 이틀(10-01, 10-06) 동안 같은 교실에서 모은 것이다. 장소·조명이 다른 환경에서는 다시 재야 한다.

### 3.3 상태 전환 분포 (전체 1,716건)

| 전환 | 횟수 |
|---|---|
| 정상 → 경고 | 449 |
| 경고 → 정상 | 447 |
| 오류 → 정상 | 202 |
| 정상 → 오류 | 201 |
| 오류 → 경고 / 경고 → 오류 | 177 / 177 |

정상↔경고 전환이 가장 많다. 경고 거리(50~200cm)에서 얼굴이 작게 찍혀 검출이 자주 끊긴 결과로 본다.

## 4. 오탐·미탐 사례

시연·시험 중 직접 관찰한 사례만 적었다.

### 4.1 미탐 (작업자가 있는데 검출 못 함)

|---|---|---|---|

| M2 | 경고 거리(50~200cm)에서 얼굴이 작게 찍힘 | 프레임마다 검출이 끊겨 경고↔정상 반복 | 3.2절 로그 통계 |

### 4.2 오차 (검출은 됐지만 값이 흔들림)

| 번호 | 상황 | 결과 | 근거 |
|---|---|---|---|
| E1 | 같은 사람이 같은 위치에 있음 | 추정거리가 139.8cm ↔ 342.1cm로 급변 | 2026-10-01 14:40 터미널 출력 |
| E2 | 얼굴 2명이 동시에 보임 | 가장 가까운 얼굴(309.5cm) 기준으로 판단 (설계대로 동작) | 2026-10-01 15:09 대시보드 화면 |

### 4.3 오탐 (사람이 없는데 검출)

- 시험 기간 중 **관찰되지 않았다**.
- 잠재 위험: 포스터·모니터 화면 속 얼굴도 검출될 수 있다. 이 경우 벨트가 불필요하게 멈출 수 있다(안전 쪽 오류).

### 4.4 구조적 한계 (추정)

- YuNet은 약 10~300픽셀 크기의 얼굴을 검출한다. 거리식으로 환산하면 300픽셀은 약 43cm다. 그보다 가까우면 검출이 끊길 수 있다. 다만 로그에는 30.4cm까지 검출된 기록이 있어 실제 영향은 추가 확인이 필요하다.
- 거리식의 상수 13000은 근사값이다. 얼굴 크기가 다른 사람(어린이, 큰 체형)은 거리가 다르게 추정된다.

## 5. 현장 정량 평가: Accuracy, F1, FPS

운영 로그에는 정답이 없어서, **줄자로 잰 실제 거리를 정답으로 붙인 평가 데이터**를 따로 모아 계산한다. 도구는 저장소의 `evaluate_model.py`다. `convey_vision.py`와 같은 모델·설정·거리식·상태 기준으로 프레임마다 판단하고, LED·벨트(GPIO)는 건드리지 않는다.

### 5.1 왜 이 지표인가

| 지표 | 의미 | 이 프로젝트에서 보는 이유 |
|---|---|---|
| **Accuracy** | 전체 프레임 중 상태(정상·경고·위험)를 맞힌 비율 | 시스템이 전체적으로 얼마나 맞게 판단하는지 |
| **Precision / Recall / F1** (상태별, Macro F1) | Precision: 그 상태라고 판단한 것 중 맞은 비율 / Recall: 실제 그 상태 중 찾아낸 비율 / F1: 둘의 조화평균 | 위험 프레임은 적어서 Accuracy만 보면 위험을 놓쳐도 높게 나온다. 상태별로 따로 봐야 한다 |
| **위험(red) Recall** | 실제 50cm 이내인데 위험으로 판단한 비율 (1 − 위험 미탐률) | 안전 시스템에서 가장 중요한 값. 놓치면 벨트가 안 멈춘다 |
| **FPS** | 1초에 처리하는 프레임 수. 모델만(검출 시간) / 카메라·화면 포함 | 실시간으로 반응할 수 있는지 |
| 거리 오차(MAE) | \|추정거리 − 실제거리\|의 평균 | 거리식(13000 ÷ 상자 높이)의 정확도 |

> **위치별 결과**로 거리별 검출률도 함께 나온다.
>
> mAP는 계산하지 않는다. 프레임마다 얼굴 상자 정답을 손으로 그려야 해서 라벨링 비용이 크다. 이 시스템의 최종 출력은 상자가 아니라 **상태**라서, 상태 기준의 Accuracy·F1이 목적에 더 맞다.

### 5.2 데이터 수집 방법

| 위치 | 정답 상태 | 이유 |
|---|---|---|
| 빈 화면(사람 없음) | 정상 | 오탐 확인 |
| 300cm, 250cm | 정상 | 200cm 초과 |
| 150cm, 100cm, 70cm | 경고 | 50~200cm |
| 40cm, 30cm | 위험 | 50cm 이하 |

- 기준선(50cm, 200cm) 바로 위는 줄자 오차로 정답이 애매해서 피했다.
- 위치마다 **프레임 60장**을 저장한다(총 8곳 × 60 = 480장). 바닥에 줄자로 거리를 표시하고, 카메라 정면에 선다.
- 사진은 저장하지 않는다. 프레임마다 판단 결과만 `frames.csv`에 남긴다(개인정보 보호).
- 조명·각도·사람을 바꿔 반복하면 더 믿을 만하다.

```bash
# convey_vision.py를 먼저 끈다(카메라는 한 프로그램만 열 수 있음). Jetson 모니터에서 실행
cd ~/Dokkab
conveyor_dashboard/.venv/bin/python evaluate_model.py
#   화면의 TARGET 위치에 서고 Space → 5초 뒤 60장 자동 저장 (n: 건너뛰기, q: 종료)
#   결과: eval_results/<시각>/frames.csv, metrics.md

# 저장된 CSV로 지표만 다시 계산 (PC에서도 가능)
python evaluate_model.py --score eval_results/<시각>/frames.csv
```

**FPS 측정 조건 (2026-10-06)**

- 워밍업 30프레임 뒤 300프레임씩 2회 측정했다. 화면에는 얼굴이 1~4개 있었다.

- 모델만 37 FPS로 카메라(22fps)보다 빠르다. 따라서 지금 속도의 한계는 모델이 아니라 카메라와 화면 표시다.
- TensorRT 변환 전후 비교(저장 프레임 기준 OpenCV 71.3 FPS, TensorRT FP16 87.9 FPS, CPU 사용 558% → 65%)는 [최적화 모델](10_최적화_모델.md)과 [벤치마크 결과](11_벤치마크_결과.md)에 있다.

**Accuracy·F1·Recall·MAE가 아직 비어 있는 이유**: 줄자로 잰 위치(빈 화면, 300·250·150·100·70·40·30cm)에 사람이 직접 서야 정답이 생긴다. 원격으로는 잴 수 없어서 값을 비워 두었다. Jetson 모니터 앞에서 5.2절 명령으로 측정한 뒤 `metrics.md`의 혼동행렬·상태별 지표·위치별 결과를 이 절에 붙인다.
>
> 계산 코드는 손으로 계산할 수 있는 가짜 데이터 30장으로 검증했다(2026-10-06). Accuracy 80.0%, Macro F1 0.800, MAE 19.3cm가 손계산과 일치했다. 이 값은 검증용이며 실제 결과가 아니다.

## 6. 결론

- YuNet은 정면 얼굴을 안정적으로 검출하며, 위험 거리(50cm 이하)에서 벨트 정지가 정상 동작했다(DANGER 40건 모두 정지 기록, 10-06 조회).
- 가장 큰 문제는 경고 거리에서의 **검출 끊김에 따른 상태 깜빡임**이었다. 1초 안정화 필터 적용 후 1초 미만 반전 비율이 81.5%에서 16.7%(10-01, 39건)로 낮아졌고, 10-06까지 모은 507건으로 다시 계산하니 13.5%였다. 남은 빠른 전환은 모두 더 위험해지는 방향이다.
- 처리 속도는 모델만 약 37 FPS, 카메라 포함 22.1 FPS로 실시간 판단에 충분하다. 상태 판단 정확도(Accuracy·F1)는 현장 측정이 남아 있다.
- 얼굴이 안 보이는 작업자(M1)는 구조적으로 검출할 수 없다. 사람 전체를 검출하는 모델(예: YOLO person)과 함께 쓰는 것이 개선 방향이다.
