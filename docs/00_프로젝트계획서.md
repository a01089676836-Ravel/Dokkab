## 1. 프로젝트 개요

- **프로젝트명**: 비전 AI 기반 컨베이어 작업자 접근 감지 및 안전 알림 시스템
- **팀장**: 전종현
- **담당파트**: 시스템 아키텍처, FSM·대시보드 구현 및 통합

| 이름 | 담당 내용 |
|---|---|
| 전종현 | 전체 아키텍처, 상태 판단(FSM), 대시보드, 데이터 기록 및 통합 |
| 송태원 | 회로 구성 및 Jetson 보드 연결 |
| 장호영 | 비전 AI 작업자 검출 및 거리 측정 |

## 2. 문제 정의

작업자가 컨베이어 장비에 가까워지는 상황을 제때 알아차리지 못하면 충돌이나 끼임 사고가 발생할 수 있다. 카메라로 작업자의 얼굴을 검출하고 장비와의 거리를 추정해, 접근 시 경고를 표시하고 위험 거리에서는 벨트를 정지하는 시제품을 구현한다.

## 3. 구현 목표

1. 카메라 영상에 OpenCV YuNet 얼굴 검출을 적용하고, 얼굴 상자 높이로 작업자 거리를 추정한다.
2. 상태 판단은 정상·경고·위험 3단계로 구분한다. 얼굴이 없으면 작업자가 없는 것으로 보고 정상으로 처리한다. 얼굴 검출이 잠깐 끊겨 상태가 깜빡이지 않도록, 위험해지는 쪽은 즉시, 안전해지는 쪽은 1초 유지된 뒤에 바꾼다. (오류는 대시보드가 영상·상태 연결이 끊긴 것을 화면에 표시할 때 쓴다.)
3. 출력 장치는 빨강·노랑 LED와 DC 모터(컨베이어 벨트)만 사용한다. 경고는 노랑 LED로 알리고 벨트는 계속 돌린다. 위험은 빨간 LED를 켜고 벨트를 정지한다.
4. 상태가 바뀔 때마다 날짜·시간·상태·설명과 장비 정지 여부·사유를 Aiven MySQL에 기록한다. HTML 대시보드는 카메라 영상, 현재 상태(신호등), 이벤트 기록을 보여 주고, 기록은 최신이 위에 오도록 표시한다.

## 4. 사용 기술 및 개발 환경

- **하드웨어**: NVIDIA Jetson Orin Nano, USB 웹캠, 브레드보드 회로, 빨강·노랑 LED, L9110S 모터 드라이버, DC 모터(컨베이어 벨트)
- **개발 환경**: Windows PC(VS Code Remote-SSH) + Jetson 보드 시험 환경
- **개발 도구**: Python 3.10, OpenCV 4.14.0 FaceDetectorYN(YuNet), Jetson.GPIO, Flask, PyMySQL, HTML 대시보드, cloudflared(인터넷 임시 주소)
- **주요 구성**: YuNet ONNX 얼굴 검출 → 거리 추정 → 상태 판단 → LED·벨트 제어 → Aiven MySQL 기록 → HTML 대시보드 (모두 `convey_vision.py` 한 프로그램에서 실행)
- **YuNet 설정값**: 모델 `face_detection_yunet_2023mar.onnx`, 카메라 인덱스 0, score threshold 0.8, NMS threshold 0.3. 모델 파일이 없거나 10KB 미만이면 다시 내려받는다.
- **거리 기준**: 추정거리(cm) = 13000 ÷ 얼굴 상자 높이(px). 50cm 이하 위험, 200cm 이하 경고.
- **제어 원칙**: 상태 판단과 LED·벨트 제어는 `convey_vision.py`만 한다. 대시보드는 LED·벨트를 직접 켜고 끄지 않는다. 대시보드가 장비에 영향을 주는 동작은 두 가지뿐이고 둘 다 비밀번호가 필요하다.
  - **대시보드 종료**: 프로그램을 끈다. 끄는 과정에서 벨트를 멈추고 핀을 정리한다.
  - **DB 연동 켜기·끄기**: 이벤트 기록만 켜고 끈다.

### HTML 대시보드 화면 구성

| 위치 | 표시 내용 |
|---|---|
| 위쪽 머리글 | 제목, 장치 이름, 시계, DB 연결 상태, **[DB 연동] [대시보드 종료]** 버튼(비밀번호 필요) |
| 왼쪽 위 | 카메라 영상(Jetson 화면, 얼굴 상자·거리 표시). "이 PC 카메라 연결"은 보는 PC의 카메라로 화면만 시험하는 버튼이다 |
| 왼쪽 가운데 | 현재 상태 카드(상태, 이유, 시각)와 **신호등**: 빨강 위험·정지 / 노랑 경고·작동(브레드보드 노랑 LED와 같은 색) / 초록 정상·작동 |
| 왼쪽 아래 | 화면 시연: 정상·경고·위험·오류 화면을 미리 보여 준다. DB에 저장되지 않고 장비도 움직이지 않는다 |
| 오른쪽 | 이벤트 기록 표(날짜·시간·상태·내용, 정지 때는 정지 이유 포함). 최신 기록이 맨 위. 상태 필터(전체·경고·위험·오류), 전체·경고·정지 건수, **기간 검색**(최근·오늘·1주·1개월·3개월·달력으로 직접 지정) |

- **갱신**: 기록은 5초마다(평소에는 최근 100건, 기간 검색은 최대 500건), 현재 상태는 1초마다 다시 불러온다.
- **접속 방법**
  - Jetson 안: `http://127.0.0.1:5080`
  - 같은 Wi-Fi: `http://<Jetson IP>:5080`
  - 인터넷: `conveyor_dashboard/start_tunnel.sh`를 실행하면 나오는 `https://….trycloudflare.com` 주소. 실행할 때마다 주소가 바뀐다.
- **버튼 보안**: 비밀번호는 `.env`의 `DASHBOARD_PASSWORD`이고 저장소에 올리지 않는다. 비밀번호가 틀리면 401로 거절한다. 다른 사이트에서 보낸 요청은 전용 헤더가 없어서 403으로 거절한다.
- **종료 후 다시 시작**: `launcher.py`로 실행하면 종료 뒤 같은 주소에 [다시 시작] 화면이 뜬다. 비밀번호를 넣으면 `convey_vision.py`가 다시 켜진다.

## 5. 개발 계획 (수정)

- **1주차**: 요구사항과 데이터 형식을 확정한다. 센서·서보를 범위에서 제외하고 카메라 기반 구조로 정리한다.
- **2주차**: YuNet 코드로 카메라 입력과 얼굴 검출을 단독 시험한다. 카메라 인덱스·해상도·임계값을 확인하고 거리 추정식을 정한다.
- **3주차**: 비전·상태 판단·대시보드·DB를 연결한다. 정상·경고·위험 흐름을 로그로 확인한다.
- **4주차**: 배선과 핀 설정을 확인한 뒤 LED·벨트 출력을 시험한다. 상태 깜빡임을 안정화하고, 통합 로그를 대조해 시연 자료와 제한사항을 정리한다.
