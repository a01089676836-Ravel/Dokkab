# DB 구조

## 1. 구성

```
convey_vision.py ──record()──▶ Jetson 로컬 대기함 (SQLite, jetson_log_outbox.sqlite3)
                                     │ 별도 스레드가 5초 간격으로 전송
                                     ▼
                              Aiven MySQL (클라우드)
                              테이블: conveyor_event_logs
                                     ▲
HTML 대시보드 ──GET /api/v1/logs──▶ app.py ──SELECT──┘
```

- **로컬 대기함을 먼저 거치는 이유**: 인터넷이 끊겨도 기록이 사라지지 않는다. 연결되면 원래 발생 시각 그대로 다시 보낸다. 벨트 제어 루프가 네트워크를 기다리며 멈추지도 않는다.
- **연결 보안**: CA 인증서(`ca.pem`)로 서버 인증서와 서버 이름을 검증하는 암호화 연결을 쓴다.
- **개인정보**: 영상과 얼굴 사진은 저장하지 않는다. 문자 이벤트만 저장한다.

## 2. 테이블: `conveyor_event_logs`

```sql
CREATE TABLE IF NOT EXISTS conveyor_event_logs (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    event_id CHAR(36) NOT NULL,
    device_id VARCHAR(100) NOT NULL,
    occurred_at_utc DATETIME(3) NOT NULL,
    event_date DATE NOT NULL,
    event_time TIME(3) NOT NULL,
    severity ENUM('NORMAL', 'WARNING', 'DANGER', 'ERROR') NOT NULL,
    event_description TEXT NOT NULL,
    equipment_stopped BOOLEAN NULL,
    stop_reason TEXT NULL,
    received_at_utc DATETIME(3) NOT NULL,
    UNIQUE KEY uq_device_event (device_id, event_id),
    KEY idx_occurred (occurred_at_utc, id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

| 필드 | 형식 | 의미 | 예시 |
|---|---|---|---|
| `id` | BIGINT | DB 자동 번호 | 1544 |
| `event_id` | CHAR(36) | 이벤트 UUID. 재전송 중복 방지 | `9bac55af-...` |
| `device_id` | VARCHAR | 장치 이름 | `jetson-orin-nano-01` |
| `occurred_at_utc` | DATETIME(3) | 실제 발생 시각 (UTC) | 2026-10-01 08:16:41.123 |
| `event_date` | DATE | 발생 날짜 (KST) | 2026-10-01 |
| `event_time` | TIME(3) | 발생 시간 (KST) | 17:16:41.123 |
| `severity` | ENUM | 상태 | DANGER |
| `event_description` | TEXT | 무슨 일이 있었는지 | 얼굴 1명 검출 · 가장 가까운 추정거리 49.6cm |
| `equipment_stopped` | BOOLEAN | 벨트 정지 명령을 적용했는지 | 1 |
| `stop_reason` | TEXT | 정지 이유 (정지일 때 필수) | 작업자 위험 접근(50cm 이하) |
| `received_at_utc` | DATETIME(3) | DB가 받은 시각 | 2026-10-01 08:16:42.010 |

### 설계 포인트

- **발생 시각과 수신 시각을 분리**: 인터넷이 끊겼다가 나중에 전송돼도 실제 발생 시각이 유지된다.
- **`(device_id, event_id)` 유일 키**: 같은 이벤트를 다시 보내도 한 번만 저장된다(`ON DUPLICATE KEY UPDATE`).
- **`occurred_at_utc` 인덱스**: 최신순 조회를 빠르게 한다.
- **입력값 검증**: 정지 이벤트(`equipment_stopped = true`)는 정지 이유가 없으면 저장하지 않는다.

## 3. 기록 시점

| 시점 | severity | equipment_stopped | stop_reason |
|---|---|---|---|
| 정상으로 바뀜 (얼굴 없음 / 200cm 초과) | NORMAL | false | — |
| 경고로 바뀜 (50~200cm) | WARNING | false | — |
| 위험으로 바뀜 (50cm 이하) | DANGER | true | 작업자 위험 접근(50cm 이하) |
| 프로그램 종료 | NORMAL | true | 프로그램 종료 |

- 매 프레임이 아니라 **상태가 바뀔 때만** 기록한다.
- 대시보드의 **DB 연동 끔** 상태에서는 새 이벤트를 기록하지 않고 전송도 멈춘다.

## 4. 조회 방식

### 4.1 대시보드 API

`GET /api/v1/logs?limit=100` — 이 장치의 최근 이벤트를 발생 시각 최신순으로 돌려준다(최대 500건). 대시보드는 5초마다 호출한다.

`GET /api/v1/logs?limit=500&from=2026-09-06&to=2026-10-06` — 기간 검색. `from`·`to`는 한국 날짜(YYYY-MM-DD)이고 양 끝 날짜를 포함한다. 서버가 UTC로 바꿔 `occurred_at_utc`로 거른다(예: 09-06 0시 KST = 09-05 15:00 UTC). 응답의 `total`은 기간 안 전체 건수, `items`는 그중 최신 500건까지다. 날짜 형식이 틀리거나 시작이 끝보다 늦으면 400을 돌려준다.

```sql
SELECT * FROM conveyor_event_logs
WHERE device_id = %s
  AND occurred_at_utc >= %s AND occurred_at_utc < %s   -- 기간 검색일 때만
ORDER BY occurred_at_utc DESC, id DESC
LIMIT %s;

SELECT COUNT(*) AS total FROM conveyor_event_logs
WHERE device_id = %s AND occurred_at_utc >= %s AND occurred_at_utc < %s;  -- 기간 전체 건수
```

대시보드의 **기간** 줄에서 [오늘]·[1주]·[1개월]·[3개월]을 누르면 오늘까지의 기간이 달력 칸에 채워지고 바로 검색된다. 달력으로 시작·끝 날짜를 직접 고른 뒤 [검색]을 눌러도 된다. [최근]은 처음 상태(최근 100건)로 돌아간다.

### 4.2 직접 조회 예시

```sql
-- 최근 정지 기록
SELECT event_date AS 날짜, event_time AS 시간, severity AS 상태,
       event_description AS 내용, stop_reason AS 정지이유
FROM conveyor_event_logs
WHERE device_id = 'jetson-orin-nano-01' AND equipment_stopped = 1
ORDER BY occurred_at_utc DESC
LIMIT 20;

-- 상태별 건수
SELECT severity, COUNT(*) AS 건수
FROM conveyor_event_logs
WHERE device_id = 'jetson-orin-nano-01'
GROUP BY severity;
```

## 5. 현재 저장 현황 (2026-10-06 15:42 KST 조회)

| severity | 건수 | 정지 기록 | 10-01 조회 때 |
|---|---|---|---|
| NORMAL | 908 | 16 (프로그램 종료 시 정지) | 675 / 9 |
| WARNING | 855 | 49 (경고 시 정지하던 초기 정책) | 639 / 49 |
| DANGER | 40 | 40 | 19 / 19 |
| ERROR | 383 | 0 | 383 / 0 |
| **합계** | **2,186** | **105** | 1,716 / 77 |

- DANGER 40건은 모두 정지 기록이 있다. 위험으로 판단했는데 벨트를 멈추지 않은 기록은 없다.
- WARNING 정지 49건은 10-01 이전 기록 그대로다. "경고 시 작동 유지"로 바꾼 뒤 경고 정지는 새로 생기지 않았다.
- ERROR는 10-01 이후 새로 생기지 않았다(얼굴 미검출을 NORMAL로 기록하도록 바꾼 뒤).
