# 데이터셋 설명서

## 1. 개요

이 프로젝트는 모델을 **직접 학습하지 않았다**. OpenCV Zoo가 배포하는 사전학습 얼굴 검출 모델 YuNet을 그대로 사용했다. 그래서 데이터는 두 종류로 나뉜다.

| 구분 | 데이터 | 용도 |
|---|---|---|
| A | YuNet 사전학습 모델의 공개 평가 정보 | 모델 선택 근거 |
| B | 프로젝트 운영 로그 (Aiven MySQL `conveyor_event_logs`) | 시스템 동작 분석·평가 |
| C | 정답 거리를 붙인 평가 데이터 (`evaluate_model.py`, 5장) | Accuracy·F1·FPS 측정 |

## 2. A. 사전학습 모델 (YuNet)

| 항목 | 내용 |
|---|---|
| 모델 파일 | `face_detection_yunet_2023mar.onnx` (약 227KB) |
| 배포처 | OpenCV Zoo (`opencv/opencv_zoo`, models/face_detection_yunet) |
| 라이선스 | MIT |
| 클래스 | 얼굴 1개 클래스 (출력: 상자 x·y·w·h, 랜드마크 5개, 점수) |
| 검출 가능한 얼굴 크기 | 약 10×10 ~ 300×300 픽셀 (공식 문서 기준) |
| 공개 평가 | WIDER Face 검증 세트 AP 0.834(easy) / 0.824(medium) / 0.708(hard) |
| 학습 데이터 | 공식 문서에 명시되어 있지 않음 |

> 출처: https://github.com/opencv/opencv_zoo/tree/main/models/face_detection_yunet
> 공식 문서의 평가 표에는 모델 버전에 따라 다른 수치도 있다. 위 수치는 README 본문에 적힌 값이다.

## 3. B. 프로젝트 운영 로그

### 3.1 수집 방법

- Jetson에서 비전 프로그램이 돌면서 **상태가 바뀔 때마다** 이벤트 1건을 만든다(매 프레임 저장하지 않음).
- 이벤트는 Jetson 로컬 대기함(SQLite)에 먼저 저장되고, 별도 스레드가 Aiven MySQL로 전송한다. 네트워크가 끊겨도 기록이 사라지지 않는다.
- **영상과 얼굴 사진은 저장하지 않는다.** 날짜·시간·상태·설명 같은 문자 정보만 저장한다.

### 3.3 클래스(상태)와 라벨 기준

상태 라벨은 사람이 붙인 정답이 아니라 **시스템이 추정거리로 자동으로 붙인 값**이다.

| 상태 | 라벨 기준 | 건수 | 정지 기록 |
|---|---|---|---|
| NORMAL | 얼굴 없음 또는 추정거리 200cm 초과, 프로그램 종료 | 675 | 9 (종료 시 정지) |
| WARNING | 추정거리 50cm 초과 ~ 200cm 이하 | 639 | 49 |
| DANGER | 추정거리 50cm 이하 | 19 | 19 |
| ERROR | 얼굴 미검출(초기 정책), 카메라 열기 실패, 하드웨어 명령 실패 | 383 | 0 |

> 정책 변경으로 같은 상태라도 시기에 따라 의미가 다르다.
> - 초기에는 얼굴이 안 보이면 ERROR로 기록했다(378건). 현재는 "작업자 없음"으로 보고 NORMAL로 기록한다.
> - 초기에는 경고에서도 벨트를 정지했다(WARNING 정지 49건). 현재는 경고에서 벨트를 계속 돌린다.

### 3.4 저장 항목

| 필드 | 의미 |
|---|---|
| `event_id` | 이벤트 고유 번호(UUID). 재전송해도 중복 저장되지 않음 |
| `device_id` | 장치 이름 |
| `occurred_at_utc` | 발생 시각(UTC, 밀리초) |
| `event_date`, `event_time` | 발생 날짜·시간(KST) |
| `severity` | NORMAL / WARNING / DANGER / ERROR |
| `event_description` | 설명. 검출 얼굴 수와 가장 가까운 추정거리 포함 |
| `equipment_stopped` | 벨트 정지 명령 적용 여부 |

## 4. 데이터 분할

학습을 하지 않았으므로 학습/검증/시험 분할은 없다. 대신 **동작 정책이 바뀐 시점**을 기준으로 운영 로그를 나눠 비교한다.

| 구간 | 기간 (KST) | 건수 | 용도 |
|---|---|---|---|
| 필터 적용 전 | 2026-09-30 12:15 ~ 2026-10-01 16:56 | 1,677 | 상태 깜빡임 문제 분석 |
| 필터 적용 후 | 2026-10-01 16:56 ~ 17:18 | 39 | 개선 효과 확인 (예비) |
| 필터 적용 후 전체 | 2026-10-01 16:56 ~ 2026-10-06 15:41 | 507 | 개선 효과 재계산 (03 모델 평가서 3.2절) |

> 10-06 조회 기준 전체 이벤트는 2,184건이다. 필터 적용 후 로그는 10-01(44건)과 10-06(463건) 이틀에 모였다.

## 5. 한계와 보완 계획

- **실제 거리 정답이 없다.** 운영 로그의 거리는 추정값이라, 거리 오차나 정확도(AP·mAP)를 계산할 수 없다.
- **C. 평가 데이터** (`evaluate_model.py`): 정답 상태를 사람이 정한 유일한 데이터다.
  - 줄자로 잰 8개 위치(빈 화면, 300·250·150·100·70·40·30cm)마다 프레임 60장을 판단한다.
  - 라벨 기준은 실제 거리다. 빈 화면과 200cm 초과는 정상, 50~200cm는 경고, 50cm 이하는 위험이다.
  - 저장 항목: 위치, 실제 거리, 정답 상태, 검출 얼굴 수, 추정거리, 판단 상태, 검출 시간(ms). 사진은 저장하지 않는다.
  - 학습을 하지 않으므로 전부 시험(test) 데이터로 쓴다. 측정 방법과 지표는 [모델 평가서](03_모델_평가서.md) 5장에 있다.
- **보완 계획**: 저장소의 `yunet_distance_calibration.py`로 정답 거리가 붙은 보정 데이터를 모은다.
  - 5.00m에서 0.50m까지 0.45m 간격(11개 위치)으로 서서 사진과 얼굴 상자 크기를 저장한다.
  - 결과 `face_samples.csv`(실제 거리, 상자 크기)로 거리 추정식을 다시 맞추고 오차를 계산한다.
  - 조명(밝음/어두움), 각도(정면/측면), 사람 수를 바꿔 반복한다.
